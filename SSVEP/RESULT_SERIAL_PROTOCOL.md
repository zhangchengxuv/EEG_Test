# SSVEP 分类结果串口协议 v1

这条链路用于“分类电脑 → 另一台上位机”，与采集板发送 `channel:...` 的串口独立。ESP32 固件及采集协议无需修改。

## 接线与串口参数

两台电脑各插一个 USB 转串口，分别使用各自电脑显示的 COM 号；两个 COM 号不需要相同。分类电脑还保留采集板自身的 USB 连接，因此采集口和结果口必须不同。

- USB 转 TTL：两端使用相容电平，A 的 TX 接 B 的 RX，A 的 RX 接 B 的 TX，GND 接 GND；两电脑端供电时不连接两模块的 VCC。
- USB 转 RS-232（通常为 DB9）：使用匹配的交叉串口线（null-modem）；常见双 DTE 三线连接为 2↔3、3↔2、5↔5，接线以转接器说明为准。
- TTL 和 RS-232 使用不同电平，不能直接混接。

参数为 **115200、8 数据位、无校验、1 停止位（8N1）、无软/硬流控**。波特率可在发送界面或命令行修改，接收端须设置相同值。

## 消息格式

ASCII 文本，英文逗号分隔，无空格，每条以两个实际字节 `0D 0A`（CRLF）结束：

```text
RESULT,42,EEG,3,15.00\r\n
```

上面的 `\r\n` 表示换行字节，不是要发送四个可见字符。

| 字段 | 类型 | 含义 |
|---|---|---|
| `RESULT` | 固定文本 | 消息标识 |
| `42` | 正整数 | 序号从 1 开始，每次完整写入递增；重新连接后从 1 开始 |
| `EEG` | 固定文本 | 当前发送程序统一填写 `EEG`，包括脑电模式、鼠标测试模式及模拟源；不用于区分本机实际来源 |
| `3` | 整数 0–4 | 0 无有效结果/停止，1 左肩，2 右肩，3 左肘，4 右肘 |
| `15.00` | 两位小数 | 目标刺激区的频率，单位 Hz；编号 0 时固定为 `0.00` |

频率随当前刺激方案和刷新率确定，不应只凭频率硬编码目标编号。例如默认 60 帧/秒方案下，1–4 为 8.57、12.00、15.00、20.00 Hz；宽频方案为 8.00、13.00、18.00、23.00 Hz。这里输出的是分类标签对应的刺激频率，不是功率谱主峰。

本机界面与会话日志继续保留真实数据源和运行模式；串口字段 `EEG` 是接收端约定的统一标记。附带的解析器为兼容旧记录仍可读取旧版 `TEST`/`SIM` 帧，当前 `run_demo.py` 不再发送这两个标记。

```text
RESULT,1,EEG,0,0.00\r\n
RESULT,2,EEG,3,15.00\r\n
RESULT,3,EEG,3,15.00\r\n
RESULT,4,EEG,0,0.00\r\n
```

以上分别为等待确认、左肘、左肘心跳、未确认或停止。重复的目标编号表示当前状态仍有效，不代表需要重复启动一次动作。

## 发送与失效规则

- 连接时初始状态为编号 0；未开始实验期间保持 0。
- 当前状态变化时尽快发送；未变化时每 0.5 秒重复一次，序号仍递增。
- 多个结果在串口来不及写入时只保留最新状态，不排队补发历史动作。
- 脑电模式只发送通过确认的目标；未确认、停止、断开采集、切换模式或频率方案时归零。
- 测试模式保持最近进入的四分区，离开区域不清除；其 0.5 秒界面定时更新继续维持该状态。
- 所有正编号结果超过 1.5 秒没有新的结果更新时间戳，即使串口线程仍运行，也自动归零。
- 主动断开输出口或退出时，后台尝试发送并排空最后一条 0，再关闭端口。拔线或写入失败时可能无法发出这条 0，因此接收端必须自行处理超时。
- 接收端从最近一条合法帧起 **1.5 秒**没有新合法帧，应把当前结果视为失效。无效帧不刷新超时。
- 串口是字节流，一次读取可能是半帧或多帧；请缓存到 `\n` 再解析。最大合法帧为 128 字节。
- 当前协议无自定义校验和、ACK 或重传。发送界面“已写入”表示完整写入本机串口，不代表另一台电脑已确认接收。

## 发送端

运行 `SSVEP/run_demo.py`，在设置中填写“结果输出串口”（例如 COM7），波特率 115200，点击“连接结果串口”；随后连接采集并开始实验。运行中连接状态及写入数量仍可见。配置项在刺激运行时锁定，停止后可修改或断开输出。

也可在 EEG_Test 根目录运行：

```powershell
# COM6 是采集板，COM7 是发给另一台电脑的 USB 转串口
.\.venv\Scripts\python.exe SSVEP\run_demo.py --port COM6 --result-port COM7

# 测试模式同样发送，协议中的模式字段仍固定为 EEG
.\.venv\Scripts\python.exe SSVEP\run_demo.py --port COM6 --mode test --result-port COM7

# 不接采集板时，可用模拟采集与鼠标测试联调结果串口
.\.venv\Scripts\python.exe SSVEP\run_demo.py --simulate --mode test --result-port COM7
```

不填写 `--result-port` 时不自动打开任何输出串口。输出失败不阻塞采集和画面，界面显示错误，停止本轮后可重新连接。会话 `session.json` 保存 `result_serial_start`、`result_serial_end` 快照及 `result_serial_mode`。

## 接收端

若已有上位机，按上述协议解析即可。本项目附带一个只显示/记录结果、不控制设备的接收示例。

将 **`receive_results.py` 和 `result_serial.py` 两个文件**复制到接收电脑的同一目录，在该目录打开终端：

```powershell
python -m pip install pyserial
python receive_results.py --list-ports
python receive_results.py --port COM5 --baud 115200

# 可选保存结果；该路径文件会重新创建
python receive_results.py --port COM5 --csv received_results.csv
```

COM5 是接收电脑自己的串口号。无需安装 PyQt5、numpy、PlatformIO 或烧录接收端固件。接收脚本支持拆包、粘包、错误帧丢弃和超时提示，Ctrl+C 退出。
